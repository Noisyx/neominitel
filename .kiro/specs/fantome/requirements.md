# Requirements: fantome (3615 FANTOME)

## Introduction
3615 FANTOME is the Halloween heart of NeoMinitel. Story: on 30 June 2012 at midnight the network was switched off, but one server never stopped. It still transmits, through a line full of ghosts. The player receives five "transmissions d'outre-tombe". Each one hides a code word, and each one is damaged by a real signal problem that only a real feature of the modem can solve.

Transmissions are generated offline as WAV files from the same cores as the app, so every level is verified to be solvable, and the hard levels are verified to be unsolvable without their feature.

**Priority tags:** `[MVP]` is needed for the demo. `[STRETCH]` is done only if time allows.

## Glossary
- **Level:** one transmission, with a story page, a damaged signal and a code word.
- **Feature:** the modem or app capability that solves a level (adaptive threshold, vote, backward channel).
- **Code row:** the row of the page that holds the code word.
- **CER:** cell error rate, as defined in the `videotex` spec.

## Requirement 1: Levels `[MVP]`
**User Story:** As a player, I want five transmissions of increasing difficulty, so that each one teaches me one thing the modem can do.

#### Acceptance Criteria
1. THE game SHALL contain these levels:

| Level | Title | Damage | Feature that solves it | Priority |
|---|---|---|---|---|
| 1 | Premier contact | None | Decoding itself | MVP |
| 2 | Parasites | Noise at moderate Eb/N0 | Reading parity error marks | MVP |
| 3 | La radio mal accordée | Frequency offset (about +380 Hz, calibrated) | Adaptive threshold ("Accord automatique") | MVP |
| 4 | Le murmure | Very low Eb/N0, page repeated 7 times | Vote over repetitions | MVP |
| 5 | La voix du retour | Code sent on the backward channel (390/450 Hz) under a decoy forward page | Backward channel listening | STRETCH |

2. EACH level SHALL have a story page in French (Videotex, with a mosaic illustration) and a hint shown by *Guide*.
3. Levels SHALL unlock in order; the progress SHALL be kept on the device (and the game SHALL still work if storage is unavailable).

## Requirement 2: Playing a level `[MVP]`
**User Story:** As a player, I want to receive a transmission on this device or from another device, so that the puzzle works alone or with a phone.

#### Acceptance Criteria
1. IN `Seul` mode, THE level's WAV SHALL be played and decoded through the normal pipeline (scheduled reveal), never by showing the original page.
2. THE player SHALL be able to play the WAV on another device (download or a link to the file) and receive it in `Écoute` mode.
3. THE simulator SHALL be disabled while a level plays, so the damage is exactly the generated one.

## Requirement 3: Code entry `[MVP]`
**User Story:** As a player, I want to type the code I read, so that I unlock the next transmission.

#### Acceptance Criteria
1. THE level's answer page SHALL offer an input field; *Envoi* SHALL check the code.
2. THE check SHALL ignore case, accents and surrounding spaces.
3. A correct code SHALL show a success page and unlock the next level; a wrong code SHALL show a "the spirits are silent" page and allow another try.
4. THE served files SHALL NOT contain any code in plain text: only salted SHA-256 hashes.

## Requirement 4: Generation `[MVP]`
**User Story:** As a developer, I want the levels generated and checked by a script, so that no level is broken or trivially solvable.

#### Acceptance Criteria
1. `scripts/generate-transmissions.ts` SHALL read `content/fantome/levels.json` and write one WAV per level plus `public/transmissions/manifest.json`.
2. THE generation SHALL be deterministic: the same inputs and seeds SHALL give byte-identical files.
3. FOR every level, THE script SHALL decode the WAV with the level's feature enabled and check that the code row is exact (CER = 0 on the code row).
4. FOR levels 3, 4 and 5, THE script SHALL decode the WAV with the feature disabled and check that the code row CER is at least 50%.
5. FOR level 2, THE script SHALL check that some error cells exist on the page but none on the code row.
6. IF a check fails, THEN THE script SHALL try the next seed (at most 50 seeds), and fail the build with a clear message if none works. The chosen seed SHALL be written to the manifest.

## Requirement 5: Atmosphere `[MVP]`
1. EACH WAV SHALL include a procedural ambient sound (low drone, under 250 Hz, at least 20 dB below the modem signal) generated by the script, so there is no third-party audio to license.
2. THE ambient sound SHALL NOT change the results of the checks in Requirement 4.

## Requirement 6: Final page `[MVP]`
1. AFTER the last available level, THE service SHALL show a final page revealing the end of the story and inviting the player to 3615 MATHS to learn how each ghost was defeated.
